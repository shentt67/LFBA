## 1. [P1] 第二轮起一直处于 eval 模式

- 位置：`utils/trainer.py:45`、`:58`、`:213`、`:260`。
- 原因：仅在整个训练循环开始前调用一次 `model.train()`；每轮结束 `test()` 调用 `eval()`，下一轮不恢复。
- 实测：用真实 `Trainer` 和含 BatchNorm 的微型模型训练两轮，每轮两批。第一轮训练的模式为 `[true, true]`，第二轮为 `[false, false]`；BatchNorm 累计更新次数仅为 2。
- 历史证据：LFBA 第 16 轮 checkpoint 中，各 BatchNorm 的 `num_batches_tracked` 均为 391，恰好是 50,000 条样本、batch_size=128 的一轮批次数；正常逐轮训练应继续更新。
- 影响：后续轮次仍反向传播并更新权重，但 BatchNorm 使用旧的运行统计量，改变正常训练行为，已有 ACC/ASR 受影响程度需要重跑对照衡量。
- 建议：每个 epoch 开始时显式将全部训练模型设为 `train()`；评测使用 `eval()`，并在评测后或下一轮正确恢复。

## 2. [P1] CIFAR 随机增强把攻击修改移到了诚实方

- 位置：`main.py:46`、`:47`；`attack/add_trigger_replace.py:51`；`dataset/dataset.py:71`；`dataset/utils.py:51`。
- 原因：先在 NHWC 原始图像右半区注入和替换，再对整张图随机裁剪、水平翻转，最后才左右切分给两方。
- 实测：对同一干净样本和替换后样本强制执行一次水平翻转，翻转前左半图无变化，翻转后左半图出现变化、右半图不变。这证明默认概率 0.5 的水平翻转一旦发生，就会跨越原定攻击边界。随机裁剪也会移动边界附近的被改区域。
- 影响：实验不再严格符合“恶意方只修改本方特征”的设定，训练和测试的触发器位置也不一致。
- 建议：明确两方特征边界和威胁模型；在共享的干净增强之后，仅对攻击方片段执行替换和触发器注入，评测保持相同语义。不要只把 NHWC 切片轴改掉——当前原始替换轴本身正确。

## 3. [P1] PHISHING 训练/测试重叠并使用了测试统计量

- 位置：`dataset/dataset.py:129`、`:134`、`:139`；`main.py:66`、`:67`。
- 原因：训练集和测试集各自构造时都重新随机抽取 8,844 条训练索引，而不是共享一次拆分；同时在拆分之前对全部数据 `fit_transform`。
- 实测：用 11,055 条带唯一行标识的合成记录替代 CSV，通过真实数据类分别创建训练集和测试集。seed=100 时，训练 8,844 条、测试 2,211 条，其中 1,774 条测试记录也存在于训练集，重叠率 80.24%。该数字是合成数据复现，不是对尚未提供的真实 PHISHING 文件的测量。
- 影响：测试精度可能严重偏高；标准化过程也使用了测试分布信息。
- 建议：只生成并保存一次固定拆分；只在训练数据拟合 scaler，再变换训练/测试数据。

## 4. [P1] LFBA checkpoint 无法正常续训

- 位置：`main.py:146`；`utils/trainer.py:63`、`:69`、`:226`。
- 原因：恢复训练时 `start_epoch` 被设为保存轮数；进入 `ep>=1` 分支会立即访问上一轮梯度，但这些属性既未初始化，也未保存到 checkpoint。固定毒化集合、索引和随机状态等同样没有保存。
- 实测：新建真实 `Trainer`，设置 `attack='LFBA'`、`start_epoch=16`，在第一批训练前直接抛出 `AttributeError: 'Trainer' object has no attribute 'grad_vec_epoch'`。
- 影响：已提供的 `--pretrained_checkpoint` 对 LFBA 不可用。简单补一个空梯度列表也不能恢复原来的攻击过程。
- 建议：保存并恢复选样/毒化状态、必要的梯度及样本顺序、目标标签、随机状态等；如选择重新计算梯度，要明确这是重新初始化攻击而非严格续训。

## 5. [P1] 独立评测入口直接报错

- 位置：`main.py:207`、`:213`、`:255`。
- 原因：访问了没有在命令行参数中声明的 `args.do_tsne`；相关分支还调用了不存在的 `Trainer.perform_tsne`。
- 实测：保留真实 `main()` 控制流，以微型数据和模型替换耗时部分，成功加载模拟 checkpoint 后，抛出缺少 `do_tsne` 的 `AttributeError`。另外确认 `hasattr(Trainer, 'perform_tsne')` 为 False。
- 影响：`--test_checkpoint` 无法直接完成独立评测。
- 建议：移除未实现的 t-SNE 分支，或完整实现其参数与方法；普通 checkpoint 评测直接进入 `trainer.test()`。

## 6. [P1] NUS-WIDE 的入口名与切分名不匹配

- 位置：`main.py:70`；`dataset/utils.py:64`、`:69`。
- 原因：入口和模型使用 `NUSWIDE`，切分函数只接受 `NUSWIDET` / `NUSWIDEI`。仅在命令行改成后两者，又会被入口拒绝。
- 实测：`split_vfl(torch.zeros(2, 1634), args(dataset='NUSWIDE'))` 抛出 `Unknown dataset, please implement it.`。
- 影响：README 主推的 NUS-WIDE 路径在准备好数据后仍无法完成首批训练。
- 建议：统一数据集标识，并明确攻击哪一方；同一标识贯穿读取、模型、触发器和切分。

## 7. [P2] checkpoint 缺少恢复正确 ASR 所需的实验配置

- 位置：`utils/trainer.py:139`、`:226`、`:305`；`main.py:242`。
- 原因：LFBA 根据锚点将目标标签改为 6，但保存文件里没有 `target_label`、触发维度和完整参数；单独评测默认目标类为 3。
- 实测：已读取历史 LFBA checkpoint，其键仅包含 `epoch`、`best_acc`、`test_trade_off`、`test_target`、`poison_acc`、`asr`、`state_dict`、`optimizer`。日志显示目标标签 6，而默认参数为 3。
- 影响：即使修复第 5 项，只加载权重也无法自动复现原 ASR；表格数据随机触发维度也可能重新抽取为另一组。
- 建议：保存和恢复完整实验配置、触发器及目标标签，并对手动覆盖关键配置给出明确说明。

## 8. [P2] “余弦相似度”的实现使用 L1 范数

- 位置：`attack/attack.py:80`—`:85`。
- 原因：分子为点积，分母用双方 L1 范数，和标准余弦的 L2 归一化不同；没有防止零范数除零。
- 实测：锚点 `[1,0,0]`，候选 `[1,1,1]` 与 `[1,1.9,0]`，当前函数选择后者，而标准余弦选择前者。输入含零梯度行时，当前 top-k 可选中产生 NaN 的零行。
- 影响：选出的毒化候选集合可以不同，不能把当前排序解释为标准余弦排序。
- 建议：先明确需要复现的是原实现还是标准余弦；若按余弦实现，用 L2 归一化并处理零向量。更改此项会改变攻击算法，应保留双版本对照。

## 9. [P2] RSA 意外原地修改传入数据

- 位置：`attack/attack.py:31`、`:34`。
- 原因：虽然先做了深拷贝，调用触发器时却传入原始 `data` 而不是拷贝 `new_data`。
- 实测：对两个全零 CIFAR 图像调用 `attack_rsa` 后，原数组发生变化，且返回对象与输入为同一对象。
- 影响：调用者保留的干净数组、同一对象的其他引用会被污染；当前主路径通过深拷贝 ASR 数据集缓解了部分影响，但函数副作用仍存在。
- 建议：传入拷贝后的数组；用输入不变性检查保护此接口。

## 10. [P2] 多个配置项与实际行为不一致

- `--select_replace`（`main.py:252`）只被声明、不被读取；是否替换由 `poison_all` 决定，无法按 README 解释控制消融。
- `--pretrain_stage`（`utils/trainer.py:39`、`:62`、`:239`）只影响日志和早停计数，实际 LFBA 仍在 `ep=1` 开始投毒，不会等待所设预训练轮数。
- `--results_dir`（`main.py:259`）解析后总被重写，用户指定路径不生效。
- `--client_num` / `--attack_client_num` 缺少能力约束：切分和全局模型实际按两方实现，触发与替换也固定在后半部分，修改客户端数量或将攻击方设为 0 并不会相应改变所有攻击操作（`dataset/utils.py:48`、`models/CIFAR10_models.py:14`、`attack/add_trigger_replace.py:51`）。
- 建议：实现真实参数语义，或对尚不支持的配置立即拒绝；不要保留可以运行却改变不了预期行为的开关。

## 补充实验与性能风险

1. **测试集参与模型选择**：`utils/trainer.py:213`—`:237` 每轮在测试集计算指标，再用测试集上的 `(ACC+ASR)/2` 选最佳模型；需要另划验证集用于选轮，最终测试集只做独立报告。
2. **续训最佳记录重置**：`utils/trainer.py:47` 将 `best_trade_off` 置 0，恢复时只读取 `best_acc`；非 LFBA 续训也会丢失之前最佳选择标准。
3. **缺少边界校验**：毒化率、选择率、锚点下标、触发维数等缺少有效范围检查，可能在 top-k、随机采样或锚点查找时报难理解的错误；只有目标类或没有目标类的小测试集还可能造成评测分母为零。
4. **评测仍构建梯度图**：`test()` 没有 `no_grad()`，并保留无实际用途的 `requires_grad` 输入副本，会增加显存和计算开销；这不等于已经测得 OOM。
5. **历史笔记存在过时信息**：“LFBA 尚未执行”和 CIFAR 原始切片轴错误的判断应以 `00-project-overview.md` 的校正为准；干净基线命令要省略 `--attack`，不能传字符串 `None`。
